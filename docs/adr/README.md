# Architecture decision records

Create one Markdown file per decision using the next sequential number, for example `0001-session-storage-adapter.md`.

Each ADR records:

- status and date;
- decision context and authoritative documentation;
- considered options;
- decision and consequences;
- required verification and rollback path.

An ADR is required before deviating from the dependency allowlist, changing the Expo SDK baseline, adding client state infrastructure, changing authentication/session storage, or adopting an experimental runtime policy.
